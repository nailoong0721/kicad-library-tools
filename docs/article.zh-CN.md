# KiCad 库迁移工具套件：转换 Altium 元件库，整理项目本地库

把已有的 Altium 元件库迁移到 KiCad，通常需要完成三件事：转换原理图符号、转换 PCB 封装，以及把转换结果整理进项目使用的库中。这套 Windows 图形工具分别处理这三个环节，让选择文件、批量转换、查看结果和导入前检查都可以在界面中完成。

工具适合需要复用旧元件库的硬件开发者，也适合希望把零散符号、封装和 3D 模型整理进现有 KiCad 项目库的用户。文件转换和导入在本机完成，使用时无需安装 Codex、Visual Studio 或开发 SDK。

> 本文对应 2026 年 9 月 29 日 18:06 的发布包，文档更新于 2026 年 10 月 3 日。支持基线为 Windows 10/11 64 位和完整 KiCad 10.x，本机实测 KiCad 版本为 10.0.4。转换对象是元件库；当前工具不处理整套 `.SchDoc` 原理图或 `.PcbDoc` PCB 工程。

## 三个工具分别做什么

| 工具 | 输入 | 输出或操作 | 适用场景 |
| --- | --- | --- | --- |
| AD2KiCadSchGUI：符号库转换器 | 一个 Altium `.SchLib` | 完整 `.kicad_sym`，以及每个符号一个独立库文件 | 把旧符号库迁入 KiCad，或按元件拆分保存 |
| AD2KiCadPCBGUI：封装库转换器 | 一个或多个 Altium `.PcbLib` | 每个源库对应一个 `.pretty` 文件夹，附 JSON 转换报告 | 批量整理 PCB 封装库 |
| KiCadLibraryImporter：项目库导入器 | 按要求整理的 KiCad 符号、封装及可选模型包 | 向已有项目本地库追加内容，并在提交前检查冲突 | 把多次转换得到的元件统一收录到项目库 |

前两个工具可以独立使用。转换出的 `.kicad_sym` 和 `.pretty` 可以直接通过 KiCad 的库管理器添加。需要把成套内容合并进已有项目库时，再使用第三个工具。

## 工具一：把 SchLib 转成 KiCad 符号库

### 功能介绍

`AD2KiCadSchGUI` 将一个 Altium `.SchLib` 转为 KiCad `.kicad_sym`，并自动生成逐符号拆分的库文件。完整库便于整体使用，单符号库便于按元件归档或分享。

对于双运放、逻辑门等多单元符号，工具按顶层符号拆分，全部单元仍保存在同一个文件中。文件名中的 Windows 非法字符、保留名称或重名会自动处理，库内符号名保持不变。

### 操作步骤

1. 打开 `AD2KiCadSchGUI.exe`。
2. 选择一个 `.SchLib` 源文件，也可以把文件拖到窗口中。
3. 选择新的 `.kicad_sym` 输出路径，并确认“KiCad CLI”指向正确的 KiCad 安装。
4. 点击“开始转换”，等待转换和校验完成。
5. 查看界面中的结果路径、拆分数量和日志，再用 KiCad 符号编辑器检查输出。

输出完整库和同名拆分目录都必须尚未存在。重复转换时，请换一个输出名称。

### 输出示例

假设选择输出 `MyParts.kicad_sym`，会得到如下结构。这里的元件名称仅用于说明：

```text
Converted/
├── MyParts.kicad_sym          # 包含全部符号的完整库
└── MyParts_symbols/
    ├── Resistor.kicad_sym     # 只包含 Resistor
    └── DualOpAmp.kicad_sym    # 包含 DualOpAmp 及其全部单元
```

可以通过 KiCad 符号编辑器的“管理符号库”添加完整库；只需要个别元件时，也可以添加相应的独立库文件。根据使用范围选择项目专用库或全局库。

### 校验与使用边界

转换过程中，工具使用源文件副本处理，执行 KiCad 二次保存、顶层符号名比较、SVG 渲染检查及源文件哈希复核，完成后发布输出。校验用 SVG 是临时产物，不是最终交付的图片包。

这些检查能够发现部分解析、保存和渲染问题，但不证明符号与 Altium 原始内容完全等价。KiCad 可能忽略部分 IEEE 图形、嵌入图片或参数记录，也可能调整字体、线宽和引脚显示属性。使用前请重点检查引脚编号、电气类型、多单元关系和符号外观。

## 工具二：批量把 PcbLib 转成 KiCad 封装库

### 功能介绍

`AD2KiCadPCBGUI` 可以把多个 Altium `.PcbLib` 加入队列，分别转换为 KiCad `.pretty` 封装库。它支持添加文件、添加目录，以及拖入文件或目录，并提供结果详情、重命名映射和 JSON 报告。

添加目录时只读取该目录第一层的 `.PcbLib`，不会递归查找子目录。统一输出也只是把各个 `.pretty` 放到同一个父目录，不会把多个源库合并成一个库。

### 操作步骤

1. 打开 `AD2KiCadPCBGUI.exe`，确认“KiCad CLI”路径。
2. 点击“添加文件”选择一个或多个 `.PcbLib`，或点击“添加目录”；也可直接拖入。
3. 选择输出位置：默认在每个源文件旁生成同名 `.pretty`；勾选“统一输出到”可指定共同的输出父目录。
4. 查看队列，先处理输出冲突。如果不同目录中的源文件同名，统一输出时可能指向同一目标，需要调整输入或输出安排。
5. 点击“开始转换”。批次中某个源库失败后，程序会继续处理其余有效项，已完成的库会保留。
6. 查看转换结果列表，以及“重命名映射”和“运行日志”，通过界面打开输出库或 JSON 报告。
7. 在 KiCad 封装编辑器的“管理封装库”中添加生成的 `.pretty`，检查焊盘编号、间距、钻孔、层和 3D 模型。

### 输出示例

```text
Converted/
├── Connectors.pretty/
│   ├── Connector_A.kicad_mod
│   ├── Connector_B.kicad_mod
│   └── ad2kicadpcb-report.json
└── Passives.pretty/
    ├── Resistor_Example.kicad_mod
    └── ad2kicadpcb-report.json
```

`.pretty` 是文件夹，里面每个 `.kicad_mod` 对应一个封装。报告记录转换数量、名称映射等信息；需要追查重命名或处理结果时，可以随输出库一起保留。

### 校验与使用边界

每个源库先写入临时目录，经逐封装重新加载和结构指纹检查后，再发布最终 `.pretty`。已有输出不会被覆盖。这里比较的是 **KiCad 导入后的封装对象与保存后重新加载的结果**，不能据此认定 Altium 中所有原始信息都被保留。

对于带内嵌模型的封装，转换器实现了保留 `kicad-embed://` 引用及对应嵌入数据的处理。外部模型引用仍可能指向原电脑路径，不代表外部模型文件已经被复制到输出库。请在 KiCad 中检查模型是否实际加载。

当前发布记录已验证 PCB 转换器的环境探测、界面及可移植性流程，**尚未完成真实 PcbLib 样本的完整转换验收**。建议先用一个熟悉的小型库试转并检查结果，再处理大批量文件。

## 工具三：把成套元件导入已有 KiCad 项目库

### 功能介绍

`KiCadLibraryImporter` 用于向已有的项目本地库追加符号、封装和支持格式的 3D 模型。它先检查输入和冲突，再试运行生成导入计划；计划通过后才允许正式执行。

它处理的是整个源包，没有逐元件勾选导入功能。仅有符号库或仅有封装库时，可以直接用 KiCad 库管理器添加；使用这个导入器需要同时准备两者。

### 第一步：整理源包

源包顶层必须恰好包含：

- 一个 `.kicad_sym` 符号库。
- 一个非空 `.pretty` 封装库。
- 零个或一个 `.3dmodels` 模型目录。

以下是示例结构，文件与目录名称可以按自己的情况调整：

```text
ImportPackage/
├── MyParts.kicad_sym
├── MyParts.pretty/
│   ├── Package_A.kicad_mod
│   └── Package_B.kicad_mod
└── MyParts.3dmodels/            # 可选
    ├── Package_A.step
    └── Package_B.wrl
```

使用符号转换器的完整 `.kicad_sym` 即可；不要把多个拆分符号库都放在源包顶层。源符号库、封装目录和模型目录不强制同名，但内容引用必须对应实际名称。

外部模型支持 `.step`、`.stp`、`.wrl`，文件应直接放在 `.3dmodels` 顶层。待导入封装的模型路径应整理为类似 `../MyParts.3dmodels/Package_A.step` 的形式。导入器会把符合规则的路径改为 `${KIPRJMOD}/ProjectParts.3dmodels/Package_A.step`，使其跟随项目目录。

当前导入器不支持模型子目录，也不接受任意绝对路径或 `kicad-embed://` 内嵌模型引用。**PCB 转换器能够保存的封装，不一定能原样交给导入器。** 带此类模型引用时，可先直接通过 KiCad 使用转换库；需要合并时，再把模型整理为导入器支持的外部文件和引用形式。

### 第二步：准备目标项目库

目标项目根目录需要已存在同名的符号库与封装库。假设准备导入到 `ProjectParts`：

```text
MyProject/
├── MyProject.kicad_pro
├── ProjectParts.kicad_sym
├── ProjectParts.pretty/
├── sym-lib-table
└── fp-lib-table
```

如果项目还没有这些库，先在 KiCad 符号编辑器和封装编辑器中创建有效的项目专用库，把它们保存到项目根目录，并在项目的两张库表中将昵称都设为 `ProjectParts`、指向对应路径。不要用空文本文件冒充 `.kicad_sym`。

导入器不会创建目标符号库或封装库，也不会替你添加或修复库表条目。库表缺失或没有目标昵称时会提示；即使导入完成，库表配置不正确仍可能导致 KiCad 找不到元件。

### 第三步：检查、试运行，再导入

1. 建议首次在项目副本中操作，并关闭正在编辑目标库的 KiCad 窗口。
2. 打开 `KiCadLibraryImporter.exe`，选择源包目录和目标项目目录。
3. 选择目标库名，例如 `ProjectParts`，确认“KiCad CLI”路径。
4. 点击“检查并试运行”，查看元件清单、计划数量、冲突提示和日志。试运行不向目标库提交修改，也不创建正式导入备份。
5. 如果有同名封装，先确认它与源包中的封装是否兼容。确实需要复用时，勾选“复用目标库中的同名封装（我已确认它们兼容）”，再重新试运行。
6. 试运行通过后，点击“执行导入”，核对程序弹窗中的源包、项目、目标库及数量，然后确认。
7. 等待完成。通过“打开项目目录”检查文件，通过“打开备份”查看原目标符号库备份；再回到 KiCad 检查新元件及模型。

修改路径、目标库名或复用选项后，需要重新试运行。正式导入前也会重新核对输入指纹，避免把过期的导入计划应用到已变化的文件上。

### 冲突处理规则

| 情况 | 处理方式 |
| --- | --- |
| 源符号与目标符号同名 | 阻止导入，需先整理或重命名 |
| 源封装与目标封装同名 | 默认阻止；明确选择复用后保留目标封装，不覆盖它 |
| 同名 3D 模型文件 | SHA-256 相同才复用，内容不同会阻止导入 |
| 试运行后输入发生变化 | 原计划失效，需重新检查 |

复用同名封装是按名称进行的，程序不会替你判定焊盘、尺寸和电气连接是否兼容。导入器会调整符合规则的符号封装引用，但不会自动为未分配封装的符号寻找匹配项。

### 备份范围

正式导入会在项目中创建 `.library_import_backup_<时间戳>`，其中保存的是被替换前的目标 `.kicad_sym`。新封装和新模型会追加到目标目录。

这份备份不包含完整项目，也没有一键恢复功能。不能只还原符号库就认为全部新增资产已经撤销。正式提交期间不要强制终止进程；若导入报错，应结合日志检查项目现状，不能假定所有更改都已自动回滚。

## 从转换到使用：推荐流程

1. **先小批量验证。** 各挑一个熟悉的 `.SchLib` 和 `.PcbLib`，分别转换，在 KiCad 中核对符号和封装。
2. **独立使用转换库。** 如果只需要在项目中调用这些元件，直接添加 `.kicad_sym` 和 `.pretty` 即可。
3. **需要合并时再整理源包。** 放入一个完整符号库和一个封装库，并检查封装名称及模型路径。
4. **准备项目本地目标库。** 确保目标符号库、封装库及库表已配置好。
5. **试运行并审阅结果。** 处理同名项，确认复用是否合适，再正式导入。
6. **在实际设计中检查。** 放置新符号、核对封装关联，查看焊盘和 3D 模型；工程使用时照常进行 ERC、DRC 等设计检查。

## 常见问题

### 为什么找不到 KiCad CLI？

请选中 KiCad 安装目录下的 `kicad-cli.exe` 文件，而不是文件夹或 `kicad.exe`。标准安装通常可以自动找到，自定义安装目录可手动选择。

启动时的查找顺序为：`KICAD_CLI` 环境变量、当前用户保存的有效路径、`PATH`、标准安装目录。不需要专门设置环境变量。如果手动改过路径，下次打开却又显示旧地址，请检查是否设置了 `KICAD_CLI`。

共享设置保存在 `%LOCALAPPDATA%\KiCadPortableTools\kicad-cli.txt`。换电脑后选择新电脑上的安装路径即可。

### 为什么提示 Python 或 pcbnew 不可用？

PCB 转换器需要所选 KiCad 安装自带的 Python 和 `pcbnew`，并检查它们的版本与来源。请确认安装完整、CLI 与 Python 来自同一套 KiCad，而不是单独复制了其中一个文件。

### 为什么提示输出已经存在？

两个转换器都拒绝覆盖已有结果。请选择新的输出名称或新的父目录；SchLib 转换还要求对应的 `_symbols` 目录不存在。

### 只有一个符号库，能使用项目库导入器吗？

当前导入器要求同时存在符号库和非空封装库。只有单一类型的库时，直接使用 KiCad 的“管理符号库”或“管理封装库”添加即可。

### 转换成功，为什么 3D 模型仍然缺失？

外部模型路径可能仍依赖原电脑的目录。检查模型文件是否存在、路径是否可用。准备交给导入器的模型还必须符合其 `.3dmodels` 目录及引用格式要求。

### 取消转换后有临时目录，需要怎么处理？

强制取消可能留下名称含 `.ad2kicadsch-` 或 `.ad2kicadpcb-` 的本次暂存目录。确认任务进程已经结束、目录确实属于这次任务后，再按需手动清理。

SchLib 转换若在发布两个结果之间被取消，可能只留下单符号目录；完整 `.kicad_sym` 和 `_symbols` 目录都生成才视为完成。PCB 批次取消前已完成的其他库会保留。

### 界面显示不全怎么办？

先最大化窗口，再通过滚动条访问被遮住的内容，同时确认同名 `.exe.config` 文件没有被移走。工具支持逐显示器 DPI 缩放，无需为它强行调小系统字体。
